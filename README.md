# AI Requirements Validator

Агент для статического ревью требований до разработки. Принимает документ в Markdown или PDF с текстовым слоем, выделяет проверяемые положения и формирует отчёт на русском языке в Markdown и PDF. В каждой карточке дефекта есть источник, последствие и предлагаемое исправление.

## Быстрый старт

Нужен Python 3.10+. После клонирования откройте терминал в корне репозитория.

**Windows PowerShell**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

**macOS / Linux**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Создайте ключ в [Google AI Studio](https://aistudio.google.com/api-keys) и внесите его в строку `GEMINI_API_KEY=` локального `.env`. Для прогона без оплаты выберите проект на Free Tier с отключённым биллингом. Git игнорирует `.env`. Переменные окружения имеют приоритет над файлом.

Для быстрого прогона используйте синтетический документ из репозитория. Правило в нём требует отклонять заявку с пятью участниками, а приёмочный сценарий ожидает подтверждения.

```powershell
.\.venv\Scripts\python.exe agent.py examples/meeting.md reports/demo.md
```

```bash
.venv/bin/python agent.py examples/meeting.md reports/demo.md
```

Агент создаст `reports/demo.md` и `reports/demo.pdf`. Первый аргумент задаёт входной документ. Второй задаёт путь к Markdown, от которого вычисляется имя PDF. Передавайте путь к документу организаторов для основного прогона. Пути с пробелами заключайте в кавычки.

## Модель и лимиты

По умолчанию настроена **Gemini 3.6 Flash** (`gemini-3.6-flash`). При HTTP 429 проверьте квоты проекта в Google AI Studio. Если квота модели исчерпана, укажите `GEMINI_MODEL=gemini-3.5-flash-lite` в `.env` или переменной окружения и повторите команду. В паспорте отчёта записываются выбранная модель, версия модели из ответа API и коммит агента. Извлечённый текст передаётся Gemini API. [Лимиты](https://aistudio.google.com/docs/rate-limits) · [Тарифы](https://aistudio.google.com/docs/pricing) · [Условия обработки данных](https://aistudio.google.com/docs/terms)

Markdown читается в UTF-8. Для PDF нужен текстовый слой. Сканы требуют OCR перед запуском. Агент принимает до 100 000 символов извлечённого текста. Для PDF-отчёта используется доступный шрифт с кириллицей. При необходимости передайте свой TTF через `--font путь-к-шрифту.ttf`.

## Как устроена проверка

1. **Выделение требований.** Агент нумерует строки, сохраняет привязку к страницам PDF и извлекает правила, ограничения и сценарии приёмки. Каталог содержит исходный ID, ID отчёта, краткую формулировку и цитату.
2. **Индивидуальное ревью.** Модель проверяет каждое выделенное положение по десяти критериям. Агент принимает подтверждённые оценки и повторно запрашивает только проблемные пункты. Если повторы исчерпаны, статус таких пунктов виден в отчёте.
3. **Ревью набора.** Агент сопоставляет бизнес-правила, интеграцию и приёмку. Он проверяет границы условий, покрытие сценариев, HTTP-методы, статусы и примеры ответа.
4. **Финальная сверка.** Агент ищет пропущенные пересечения правил и объединяет дубли, сохраняя ссылки на общую карточку.
5. **Сборка отчёта.** Python проверяет структуру ответа и совпадение цитат с источником. Для противоречия требуются две разные цитаты. Программа вычисляет сводку, порядок исправлений и вывод о готовности.

| Уровень | Критерии |
| --- | --- |
| Отдельное требование | Необходимость, уместность, однозначность, полнота, атомарность, выполнимость, проверяемость, корректность, единообразие, прослеживаемость |
| Набор | Полнота, согласованность, совместная выполнимость, проверяемость, ранжируемость, модифицируемость и связи |

Критерии адаптированы из [ISO/IEC/IEEE 29148:2018](https://www.iso.org/standard/72089.html), п. 5.2.5–5.2.6, и [IEEE 830-1998](https://standards.ieee.org/ieee/830/1222/), п. 4.3. Критичный дефект блокирует разработку или приёмку ключевого сценария. Существенный меняет поведение или покрытие. Малый имеет локальное влияние.

## Проверка проекта

В активированном виртуальном окружении выполните команду без ключа и сетевых запросов.

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют повторы по отдельным требованиям, отклонение карточки с одной цитатой для противоречия, отметку о непроверенных пунктах и объединение дублей.

Для сдачи приложите выданный документ, итоговый отчёт и ссылку на этот репозиторий. Прогоны модели могут различаться, поэтому паспорт отчёта фиксирует источник, модель и версию кода.
