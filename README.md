# Агент проверки требований

ИИ-агент для **статического ревью документа с требованиями** (BCC-HUB x MNU FinTech Hackathon).
Читает документ (`.md`, `.pdf`, `.docx`, `.txt`), выделяет отдельные требования, проверяет каждое и весь набор
по критериям ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE Std 830-1998 (п. 4.3) и записывает отчёт
на русском языке в **Markdown и PDF**.

- **Модель:** Google Gemini через бесплатный Google AI Studio API. По умолчанию `gemini-2.5-flash` (меняется в `.env`).
- **Язык:** Python 3.10+.

---

## 1. Быстрый старт

```bash
# 1) зависимости
python -m venv .venv
source .venv/bin/activate          # Windows (PowerShell): .venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2) ключ LLM (см. раздел 2)
cp .env.example .env               # Windows: copy .env.example .env
# откройте .env и впишите GEMINI_API_KEY

# 3) прогон одной командой
python agent.py docs/requirements.md reports/report.md
```

Результат:

| Файл | Что это |
| :--- | :--- |
| `reports/report.md` | отчёт в Markdown |
| `reports/report.pdf` | тот же отчёт в PDF (создаётся автоматически рядом) |

Прогон занимает несколько минут: на бесплатном тарифе агент намеренно делает паузы между запросами
(~10 запросов на документ). Ход работы печатается в консоль.

## 2. Как получить ключ LLM и куда его положить

1. Откройте <https://aistudio.google.com/apikey> и войдите аккаунтом Google.
2. Нажмите **Create API key** (платный тариф не нужен).
3. Скопируйте `.env.example` в `.env` и вставьте ключ:
   ```
   GEMINI_API_KEY=ваш_ключ
   GEMINI_MODEL=gemini-2.5-flash
   ```
4. Файл `.env` находится в `.gitignore` и **не попадает в репозиторий**. Ключи в код и в коммиты не вставляйте.

Если выбранная модель недоступна или лимит исчерпан — поменяйте `GEMINI_MODEL`
(актуальный список моделей и лимитов: <https://ai.google.dev/gemini-api/docs/models>).

## 3. Командная строка

```
python agent.py <файл требований> <файл отчёта> [опции]
```

| Опция | Назначение |
| :--- | :--- |
| `--no-pdf` | не создавать PDF |
| `--model NAME` | модель Gemini (вместо `GEMINI_MODEL`) |
| `--batch-size N` | требований за один запрос при проверке (по умолчанию 6) |
| `--no-cache` | игнорировать кэш ответов LLM |
| `-v` | подробный вывод |

Если вторым аргументом указан путь с расширением `.pdf`, Markdown ляжет рядом с тем же именем.
Коды возврата: `0` — успех, `2` — ошибка входного файла, `3` — ошибка работы с моделью, `4` — не настроен ключ.

Переменные `.env`: `GEMINI_API_KEY`, `GEMINI_MODEL`, `LLM_MIN_INTERVAL` (пауза между запросами, сек; для
бесплатного тарифа 6), `LLM_MAX_RETRIES`.

## 4. Как работает агент

```
документ ─► [1] нарезка ─► [2] проверка каждого ─► [3] проверка набора ─► [4] итог ─► report.md / report.pdf
```

1. **Нарезка.** LLM выделяет все отдельные требования (функциональные, нефункциональные, данные, интеграция,
   критерии приёмки, правила API), каждое с **дословной цитатой**. Агент привязывает цитату к строке и разделу документа;
   цитата, которой нет в тексте, отбрасывается. Явные идентификаторы документа (`Ф-1`…) проверяются
   отдельно — потерянные дозапрашиваются. Если номеров нет, агент присваивает `R-NNN`.
2. **Проверка каждого требования** по 10 критериям: однозначность, проверяемость, полнота, единичность,
   непротиворечивость, реализуемость, отсутствие проектных решений, необходимость и корректность,
   прослеживаемость, формат и терминология. Для проверки модель получает весь документ как контекст и
   подсказки простого линтера (расплывчатые слова, заглушки).
3. **Проверка набора** по 8 критериям: полнота, противоречия между требованиями/частями документа/примерами,
   согласованность терминов и интерфейсов, покрытие приёмкой, структура и версионность, приоритеты, риски.
4. **Итог.** Вердикт «можно ли начинать разработку» вычисляется по правилам (есть критичные дефекты → нельзя),
   модель формулирует обоснование и приоритеты исправлений.

**Защита от выдумок:** каждое замечание обязано содержать цитату из документа; агент ищет её в тексте.
Неточная цитата исправляется по оригиналу, замечание к набору без найденной цитаты отбрасывается,
а их число выводится в приложении к отчёту.

## 5. Состав отчёта

1. Паспорт прогона (документ, SHA-256, дата, модель, версия агента — тег/коммит git, команда, число вызовов LLM)
2. Как агент нарезал требования (ID в отчёте — ID в документе — формулировка — место — цитата)
3. Проверка каждого требования (критерии, матрица, подробные замечания с цитатами, строками и исправлениями)
4. Проверка всего набора требований
5. Сводка (число требований и нарушений, критичные дефекты: непроверяемые, противоречивые, неполные)
6. Итог (можно ли начинать разработку, что исправить в первую очередь)

Версия агента в паспорте берётся из git: перед финальным прогоном сделайте коммит и (по желанию) тег
`git tag v1.0.0`, чтобы в отчёте стояла чистая версия, а не `-dirty`.

## 6. Структура репозитория

```
agent.py                 точка входа
reqvalidator/
  cli.py                 аргументы, запуск, запись отчёта
  loader.py              чтение md/pdf/docx/txt, нумерация строк, поиск цитат
  pipeline.py            нарезка → проверка требований → проверка набора → итог
  prompts.py             промпты
  criteria.py            критерии (ISO 29148 / IEEE 830)
  lint.py                подсказки: расплывчатые слова, заглушки
  llm.py                 клиент Gemini: лимиты, повторы, JSON-схемы, кэш
  report.py              сборка отчёта в Markdown
  pdf.py                 Markdown → PDF (шрифты DejaVu лежат в fonts/)
tests/                   сквозной тест на заглушке LLM (без сети и ключа)
docs/requirements.md     проверяемый документ (выдан организаторами)
reports/                 сюда пишутся отчёты
```

## 7. Лимиты бесплатного тарифа и устранение проблем

- **429 / «лимит запросов»** — агент сам ждёт и повторяет запрос. Суточный лимит исчерпан — запустите завтра:
  уже полученные ответы лежат в `.cache/llm`, повторно не запрашиваются (отключается `--no-cache`).
  В паспорте отчёта видно, сколько вызовов взято из кэша.
- **Ключ отклонён (401/403)** — проверьте `GEMINI_API_KEY` в `.env`.
- **Модель не найдена (404)** — поменяйте `GEMINI_MODEL`.
- **PDF на входе без текста (скан)** — агент сообщит об этом; пропустите файл через OCR или используйте `.md`/`.docx`.
  Таблицы из PDF извлекаются как обычный текст — для лучшего качества подавайте исходник в `.md`/`.docx`.
- Результат LLM может немного отличаться от запуска к запуску даже при `temperature = 0`.

## 8. Тест без ключа

```bash
python -m tests.test_pipeline
```
Прогоняет весь конвейер, генерацию Markdown и PDF на заглушке LLM (включая «грязные» ответы:
выдуманные цитаты, пропущенные требования). Это проверка кода, **не** отчёт для сдачи.

## 9. Что сдавать

1. Ссылка на репозиторий с этим кодом.
2. Выданный документ `docs/requirements.md`.
3. Отчёт, сформированный агентом на этом документе: `reports/report.md` и `reports/report.pdf`.
